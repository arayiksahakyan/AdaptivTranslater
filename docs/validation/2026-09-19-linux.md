## Real PaddleOCR smoke

Executed after installing `requirements-ocr.txt` and downloading official weights:

```bash
PADDLE_PDX_CACHE_HOME="$PWD/.paddle-cache" \
PADDLE_PDX_MODEL_SOURCE=bos \
PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True \
.venv/bin/python -m tools.ocr_smoke
```

Input: generated 700×180 white RGB image containing `Hello world 123` in 48 px
DejaVu Sans. No screenshot, sample image file, or OCR history was saved.
Models: `PP-OCRv5_mobile_det` and `en_PP-OCRv5_mobile_rec`, CPU, four threads,
MKL-DNN disabled.

```json
{"runs": [
  {"recognized": "Hello world 123", "passed": true, "duration_ms": 2172, "detections": 1},
  {"recognized": "Hello world 123", "passed": true, "duration_ms": 223, "detections": 1}
]}
```

The above cached run succeeded with sandbox network access restricted. Initial
dependency/model downloads required authorized network access after DNS failures.
The corrected mobile model's first networked run also passed (50,243 ms including
connectivity/model download/init). These timings are observations of one synthetic
sample, not a throughput or accuracy guarantee for screen content.

Paddle warned that ccache was absent; inference still succeeded. Inspection of
installed PaddleOCR exposed its ignored-language behavior when explicit model names
are supplied. The adapter now supplies a complete English model pair and has a
regression test for language-based non-English resolution. Non-English real
inference has not been exercised.

One logging test initially failed after application-level logging was introduced:
the test configured only the root logger. It now explicitly enables the `app`
logger and confirms timings appear while default private text does not. The test
was retained; the final suite passes.
